The tkinter package ("Tk interface") is the standard Python interface to the Tcl/Tk GUI toolkit.

** Features
:PROPERTIES:
:UNNUMBERED: t
:END:
+ tkinter: Tk widgets, themed ttk widgets, canvas, event loop; in the standard library
+ PyQt / PySide: Qt 6 widgets, QML, model / view, designer files
+ wxPython, Kivy, Dear PyGui; pywebview for HTML front ends

*** LQML
The closest thing to PyQt / PySide with QML, and the only one here that also builds mobile apps. The UI is a QML file. Lisp, compiled with ECL into the app, finds items by ~objectName~ and sets their properties. From the LQML documentation and examples, not run:
#+begin_src qml
import QtQuick 2.15
import QtQuick.Controls 2.15

Item {
  width: 300; height: 200
  Button {
    objectName: "hello"
    text: "Hello"
    onClicked: Lisp.call("app:clicked")
  }
}
#+end_src

#+begin_src lisp :eval no
(in-package :app)

(defun clicked ()
  (q> |text| "hello" "Clicked")       ; QML-SET on the item named "hello"
  (qlater (lambda () (qexit))))       ; leave the event loop when idle
#+end_src

#+RESULTS:
: not run: LQML needs ECL and a Qt build; not in cl-repo

Compared with Python: PySide6's ~QQmlApplicationEngine~ plus ~@Slot~ methods is the same shape, but PySide does not target iOS. Kivy and BeeWare are the Python routes to mobile. LQML's build is ~qmake~ / Qt Creator per platform, and the docs are terse, by its users' account.
