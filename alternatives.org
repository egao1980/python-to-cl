#+TITLE: State of Common Lisp alternatives, November 2026
#+AUTHOR: Nikolai Matiushev
#+EMAIL: egao1980@gmail.com
#+OPTIONS: author:t email:t toc:2
#+PROPERTY: header-args:lisp  :session *lisp* :exports both :async

Common Lisp is a nice and expressive language and this project is an effort to promote or improve CL libraries by comparing to the corresponding Python alternatives.

Each page: the Python package's features, the third-party Common Lisp libraries, the [[https://github.com/egao1980/cl-stack][cl-stack]] ones, then examples. This page sums them up. Verdicts come from the pages; dates are as of 2026-11-23.

* Summary
:PROPERTIES:
:UNNUMBERED: t
:END:
- Mature (a widely used, maintained library covers it): HTTP clients, web servers, JSON, XML and HTML parsing, regular expressions, templates, SQL and ORM, paths, processes, threads, command lines, logging, crypto primitives, testing.
- Usable with gaps: async HTTP, web frameworks (no type-driven validation or OpenAPI), YAML, validation models, dates beyond local-time, data frames, arrays.
- Weak or partial: AWS beyond S3, machine learning, scientific computing, plotting, browser automation, system monitoring (psutil). See [[#weak-or-partial][Weak or partial]].
- Missing (no Common Lisp library at all): none of the areas below.

* By area
:PROPERTIES:
:UNNUMBERED: t
:END:
One line per page. Numbers are PyPI download ranks ([[https://hugovk.github.io/top-pypi-packages/][top-pypi-packages]], 30 days to 2026-11-01); stdlib modules have none.

** HTTP and web
- [[file+emacs:requests.org][Requests]] (#8). Mature: Dexador (0.9.16; pooling, cookies, multipart, restarts), Drakma (v2.0.10). Both HTTP/1.1 only; http2 is low level. On macOS load ~cl-stack-ssl~ first: Homebrew's OpenSSL 4 breaks cl+ssl.
- [[file+emacs:httpx.org][HTTPX / aiohttp]] (#31, #58). Gaps: Dexador has no async API (use threads). cl-async gets occasional fixes, carrier is dormant. http2 does HTTP/2, blackbird promises.
- [[file+emacs:flask.org][Flask / FastAPI]] (#162, #65). Servers mature: Hunchentoot (the default), Clack / Woo. Frameworks: easy-routes, Radiance, Reblocks, CLOG; Ningle and Caveman2 quiet since 2024. Gap: no framework derives validation and OpenAPI from types.
- [[file+emacs:boto3.org][boto3]] (#1). Weak beyond S3: ZS3 (S3, mature, small); aws-sdk-lisp generates one system per service from botocore but is alpha.

** Data formats and validation
- [[file+emacs:json.org][json / orjson]] (stdlib, #152). Mature: jzon (v1.1.4; correct, safe, fast), shasht, yason, jsown, st-json. cl-json, the most used, last changed 2022-05 and reads ~[]~, ~{}~, ~null~, ~false~ all as ~nil~.
- [[file+emacs:pyyaml.org][PyYAML]] (#12). Gaps: cl-yaml (libyaml binding) is archived; nyaml (pure Lisp) only parses.
- [[file+emacs:pydantic.org][Pydantic]] (#18). Gaps: json-mop checks slot types, no constraints; clavier validates, no models; json-schema is dormant.
- [[file+emacs:lxml.org][lxml / Beautiful Soup]] (#81, #110). Mature: Plump with CLSS and lQuery (the Beautiful Soup role), CXML (validating; XPath through Plexippus), xmls. cl-html5-parser is archived.

** Text and time
- [[file+emacs:dateutils.org][Dateutil]] (#15). local-time is the de facto standard: no recurrence, fuzzy parsing or durations. periods (ranges, recurrence) and calendar-times had commits in 2025; local-time-duration, chronicity and cl-date-time-parser are dormant.
- [[file+emacs:regex.org][re / regex]] (stdlib, #93). Mature: CL-PPCRE (the standard), one-more-re-nightmare (faster DFAs, no backreferences), str.
- [[file+emacs:jinja2.org][Jinja]] (#37). Mature: Djula (Django templates, closest to Jinja), Spinneret, CL-WHO (no auto-escaping), TEN, cl-mustache, Clip.

** Data
- [[file+emacs:sqlalchemy.org][SQLAlchemy / DB drivers]] (#86). Mature: CL-DBI + SxQL + Mito (the usual pick), Postmodern (PostgreSQL), cl-sqlite. CLSQL is old and heavy.
- [[file+emacs:pandas.org][pandas / pyarrow]] (#38, #78). Gaps: data frames in Lisp-Stat and vellum, cl-duckdb for big CSV and Parquet files, cl-csv.
- [[file+emacs:numpy.org][NumPy]] (#21). Partial: no vectorized arithmetic in the standard. MAGICL (BLAS / LAPACK, used in production), numericals (NumPy-like, SIMD), array-operations, LLA; Petalisp is research-grade, NumCL dormant.

** System
- [[file+emacs:pathlib.org][pathlib / os.path / shutil]] (stdlib). Mature: UIOP first, then cl-fad, pathname-utils, filepaths, osicat.
- [[file+emacs:subprocess.org][subprocess]] (stdlib). Mature: UIOP ~run-program~ / ~launch-program~, cmd, inferior-shell, async-process. No psutil.
- [[file+emacs:asyncio.org][asyncio]] (stdlib). No async/await; threads, futures and actors are mature: bordeaux-threads, lparallel, blackbird, sento, chanl. cl-async gets occasional fixes.
- [[file+emacs:logging.org][logging / structlog]] (stdlib, #273). Mature: log4cl (quiet upstream since 2023-03) with log4cl-extras for JSON and context fields, verbose, vom.
- [[file+emacs:click.org][Click / argparse]] (#20, stdlib). Mature: clingon (the usual pick), adopt, command-line-args, defmain, clon. unix-opts is dormant.

** Security and testing
- [[file+emacs:cryptography.org][cryptography / hashlib / PyJWT]] (#9, #36). Primitives mature, no recipes: Ironclad (v0.61, pure Lisp), cl+ssl. jose (JWT) is not installable from cl-repo.
- [[file+emacs:pytest.org][pytest]] (#25). Mature: FiveAM (most used, slow releases), Parachute, Rove. Rove's parametrize, fixtures and JUnit XML are open PRs. Prove is deprecated; Fiasco and lisp-unit2 are dormant.

* Weak or partial
:PROPERTIES:
:UNNUMBERED: t
:CUSTOM_ID: weak-or-partial
:END:
Libraries exist, but they are small, old, experimental or cover part of the job.

- PyTorch, TensorFlow, transformers: [[https://github.com/melisgl/mgl][MGL]] (active, small) and [[https://github.com/hikettei/cl-waffe2][cl-waffe2]] (experimental, last commit 2024-12). Call Python through [[https://github.com/digikar99/py4cl2][py4cl2]].
- scikit-learn, SciPy: [[https://github.com/mmaul/clml][CLML]] gets compatibility fixes only; GSLL fails to install with current CFFI ([[https://aliquote.org/post/cl-tooling-in-2025/][Common Lisp tooling in 2025]]).
- matplotlib: [[https://github.com/Lisp-Stat/plot][Lisp-Stat plot]] (Vega-Lite in a browser) or gnuplot wrappers. No native plotting library.
- Selenium / Playwright: [[https://github.com/copyleft/cl-webdriver-client][cl-webdriver-client]], last commit 2024-09.
- AWS beyond S3: aws-sdk-lisp is alpha, see [[file+emacs:boto3.org][boto3]]. Google Cloud: no library reviewed here.
- psutil: [[https://github.com/osicat/osicat][osicat]] covers a little of POSIX. Nothing portable.

* What the survey and reviews say
:PROPERTIES:
:UNNUMBERED: t
:END:
[[https://blog.djhaskin.com/blog/common-lisp-community-survey-2024-results/][Common Lisp Community Survey 2024]] (Dan Haskin, 2024-08-09, 293 respondents). No 2025 or 2026 results had been published by November 2026.
- SBCL is the daily driver of 88%.
- Dependencies: Quicklisp 63%, Ultralisp 17%, Qlot 9%, OCICL 3%.
- In use:

| Area       | Top answers                                                     | Pages                             |
|------------+-----------------------------------------------------------------+-----------------------------------|
| JSON       | cl-json 23%, jzon 19%, yason 7%, shasht 4%                      | [[file+emacs:json.org][json]]     |
| Web server | Hunchentoot 36%, Clack / Woo 7%                                 | [[file+emacs:flask.org][Flask]]   |
| Framework  | Caveman2 7%, home-grown 4%, Ningle 3%, CLOG 3%; two thirds none | [[file+emacs:flask.org][Flask]]   |
| Testing    | FiveAM 28%, Parachute 11%, Rove / Prove 7%                      | [[file+emacs:pytest.org][pytest]] |
| CLI        | clingon 9%, unix-opts 7%                                        | [[file+emacs:click.org][Click]]   |
| XML        | Plump 14%, CXML 6%, xmls 4%; 70% need none                      | [[file+emacs:lxml.org][lxml]]     |

- Wanted (the author's summary of free-form answers): GUI, ML, gRPC, cryptography, OpenAPI, better web frameworks, an AWS SDK.

Ecosystem reviews:
- vindarel, [[https://lisp-journey.gitlab.io/blog/these-years-in-common-lisp-2023-2024-in-review/][These years in Common Lisp: 2023-2024 in review]] (2025-02-17): jzon 1.0, Bordeaux-Threads API v2, Sento 3, CLOG 2.0, calendar-times; numericals, Petalisp, cl-waffe2 and Lisp-Stat for numerics. Quicklisp updated 2024-10-12 after a year's pause; ocicl, Qlot 1.5 and vend as alternatives.
- vindarel, [[https://lisp-journey.gitlab.io/blog/csv-parsing-in-common-lisp/][CSV parsing in Common Lisp, data frames]] (2026-11-07): cl-csv for simple use, DuckDB for speed, Lisp-Stat for data frames.
- [[https://aliquote.org/post/cl-tooling-in-2025/][Common Lisp tooling in 2025]] (2025-01-22): GSLL fails to install with current CFFI.

Recommended vs abandoned, from the pages' last commits:
- The usual picks are maintained: jzon (2026-03), Hunchentoot (2026-05), Plump (2026-04), CL-PPCRE (2025-06), Mito (2026-04), local-time (2026-05), clingon (2026-11), Ironclad (2026-11), Parachute (2026-07). FiveAM, the most used test framework, last changed 2024-09.
- The most used JSON library is not: cl-json (2022-05). Neither are jonathan (2020-09), NumCL (2022-10), unix-opts (2021-01), chronicity (2019-01), local-time-duration (2018-04).
- Archived or deprecated: cl-yaml, cl-html5-parser, Prove.
- Moved to Codeberg: Shinmera's libraries (Plump, Parachute, Radiance, verbose, Clip, ratify, pathname-utils); Plump and Parachute in 2025-08.

* Since 2020
:PROPERTIES:
:UNNUMBERED: t
:END:
The [[https://github.com/egao1980/python-to-cl/tree/1846916][2020 version]] of this site had two pages: Requests (Drakma, Dexador) and Dateutil (local-time, local-time-duration, chronicity, an Easter gist). Examples loaded with ~ql:quickload~ and the site ran on Read the Docs.

Now:
- 21 pages in six areas, each with last-commit dates, versions and a verdict per library, plus the cl-stack libraries.
- Dexador (2026-10) and Drakma (2026-09) are both maintained; local-time is still the de facto standard. local-time-duration (2018-04) and chronicity (2019-01) have not changed since.
- Examples load from [[https://github.com/egao1980/cl-repository][cl-repo]] (~ghcr.io/egao1980/cl-systems~) instead of Quicklisp, and run on SBCL 2.4.11. Libraries cl-repo does not carry are marked "not run".
- New pitfall: Homebrew's OpenSSL 4 breaks cl+ssl on macOS (see [[file+emacs:requests.org][Requests]]).
- The site is built from the .org pages by [[https://github.com/egao1980/cl-blog][cl-blog]] and served by GitHub Pages.

* Where cl-stack fits
:PROPERTIES:
:UNNUMBERED: t
:END:

* Loading libraries
:PROPERTIES:
:UNNUMBERED: t
:END:
Examples load libraries with [[https://github.com/egao1980/cl-repository][cl-repo]] from ~ghcr.io/egao1980/cl-systems~, not Quicklisp:

#+begin_src sh
curl -fsSL https://raw.githubusercontent.com/egao1980/cl-repository/main/install.sh | bash
mkdir demo && cd demo
echo '(defsystem "demo" :depends-on ("dexador" "cl-stack-http"))' > demo.asd
cl-repo sync
cl-repo ros +Q run
#+end_src

Then ~(asdf:load-system "dexador")~ in the REPL. ~+Q~ keeps Roswell's Quicklisp out, so a system missing from the project fails instead of loading from Quicklisp.

Libraries that are not in cl-repo are shown with their documented examples, marked "not run". Results come from SBCL 2.4.11 on macOS arm64, 2026-11-23.
