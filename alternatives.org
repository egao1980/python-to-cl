Common Lisp is a nice and expressive language and this project is an effort to promote or improve CL libraries by comparing to the corresponding Python alternatives.

Each page: the Python package's features, the third-party Common Lisp libraries, the [[https://github.com/egao1980/cl-stack][cl-stack]] ones, then examples. This page sums them up. Verdicts come from the pages; dates are as of 2026-11-23.

Looking for a job rather than a package? [[file+emacs:usecases.org][Use cases]] maps "I want to …" to the Common Lisp route, one line each, with links to the pages.

What changed since the review: [[file+emacs:updates.org][Updates]] (latest 2026-11-23).

* Summary
:PROPERTIES:
:UNNUMBERED: t
:END:
- Mature (a widely used, maintained library covers it): HTTP clients, web servers, JSON, XML and HTML parsing, regular expressions, templates, SQL and ORM, paths, processes, threads (no GIL), command lines, logging, crypto primitives, testing, grammars (esrap), CSV, protobuf (cl-protobufs), symbolic maths (Maxima).
- Usable with gaps: async HTTP, web frameworks (no type-driven validation or OpenAPI), YAML, validation models, dates beyond local-time, data frames, arrays, LLM clients and agents (cl-stack), image codecs, PDF generation, Excel, Markdown, WebSockets, Redis, email, git, configuration, terminal UIs, GUIs (many toolkits, none dominant), property tests.
- Weak or partial: deep learning, scikit-learn-style ML, SciPy-style numerics, plotting, notebooks, browser automation, cloud SDKs (AWS beyond S3 is alpha; Google Cloud and Azure clients are small or dormant), Kafka and RabbitMQ, task queues, SSH, Docker, system monitoring. See [[#weak-or-partial][Weak or partial]].
- Missing (no Common Lisp library at all): none of the 56 pages below.

* By area
:PROPERTIES:
:UNNUMBERED: t
:END:
One line per page. Numbers are PyPI download ranks ([[https://hugovk.github.io/top-pypi-packages/][top-pypi-packages]], 30 days to 2026-11-01); stdlib modules have none.

** HTTP and web
- [[file+emacs:requests.org][Requests]] (#8). Mature: Dexador (0.9.16; pooling, cookies, multipart, restarts), Drakma (v2.0.10). Both HTTP/1.1 only; http2 is low level. On macOS load ~cl-stack-ssl~ first: Homebrew's OpenSSL 4 breaks cl+ssl.
- [[file+emacs:httpx.org][HTTPX / aiohttp]] (#31, #58). Gaps: Dexador has no async API (use threads). cl-async gets occasional fixes, carrier is dormant. http2 does HTTP/2, blackbird promises. cl-stack: ~-async~ calls with ~run-promise~ / ~gather~ (cl-stack-http 0.2.0, event-protocol 0.3.0).
- [[file+emacs:flask.org][Flask / FastAPI]] (#162, #65). Servers mature: Hunchentoot (the default), Clack / Woo. Frameworks: easy-routes, Radiance, Reblocks, CLOG; Ningle and Caveman2 quiet since 2024. Gap: no framework derives validation and OpenAPI from types.
- [[file+emacs:boto3.org][boto3]] (#1). Weak beyond S3: ZS3 (S3, mature, small); aws-sdk-lisp generates one system per service from botocore but is alpha.
- [[file+emacs:websockets.org][websockets]] (#64). Usable: websocket-driver (client and server, the base of most others), Hunchensocket, Portal; Awesome-CL notes no full-featured implementation. cl-stack: ws-protocol (HTTP/1.1 and HTTP/2, deflate).
- [[file+emacs:scrapy.org][Scrapy / Selenium / Playwright]] (#1779, #634, #253). Static scraping is easy (Dexador + Plump + lQuery, scrapycl); browser automation is weak: cl-webdriver-client (2024-09), cl-cdp (new). cl-stack: browser-protocol over CDP launches Chrome and waits for pages (0.2.0).
- [[file+emacs:cloud.org][Google Cloud / Azure SDKs]] (google-api-core #102, azure-core #185). Weak: cl-google-api (new), cl-azure (2016), koazblob (2019). REST + OAuth2 works; no credential chains.
- [[file+emacs:paramiko.org][Paramiko / Fabric]] (#271, #1436). Weak: cl-ssh (pure CL, v1.0.0 in 2026-11, "use at your own risk"), conch (new); trivial-ssh is archived. OpenSSH through a subprocess is the reliable route.

** Data formats and validation
- [[file+emacs:json.org][json / orjson]] (stdlib, #152). Mature: jzon (v1.1.4; correct, safe, fast), shasht, yason, jsown, st-json. cl-json, the most used, last changed 2022-05 and reads ~[]~, ~{}~, ~null~, ~false~ all as ~nil~.
- [[file+emacs:pyyaml.org][PyYAML]] (#12). Gaps: cl-yaml (libyaml binding) is archived; nyaml (pure Lisp) only parses.
- [[file+emacs:pydantic.org][Pydantic]] (#18). Gaps: json-mop checks slot types, no constraints; clavier validates, no models; json-schema is dormant.
- [[file+emacs:lxml.org][lxml / Beautiful Soup]] (#81, #110). Mature: Plump with CLSS and lQuery (the Beautiful Soup role), CXML (validating; XPath through Plexippus), xmls. cl-html5-parser is archived.
- [[file+emacs:csv.org][csv]] (stdlib). Mature: cl-csv (the usual pick), fare-csv; cl-duckdb for big files. cl-stack: csv-protocol (dialects, streaming), sql-query-csv.
- [[file+emacs:msgpack.org][msgpack / pickle]] (#145, stdlib). Pickle role mature: cl-store, cl-marshal, cl-binary-store; cl-messagepack and cbor.lisp are small. Nothing reads Python pickles.
- [[file+emacs:protobuf.org][protobuf / gRPC]] (#34, #92). Usable: cl-protobufs (Google's, protoc plugin), qitab/grpc (C core), ag-gRPC (pure CL, new). The 2024 survey asks for "a better gRPC story". cl-stack: pure-Lisp gRPC over HTTP/2.
- [[file+emacs:markdown.org][Markdown / markdown-it-py / mistune]] (#265, #56, #358). Usable: 3bmd (the usual pick), cl-cmark and cl-commonmark-gfm (bindings), commondoc-markdown. cl-stack: markdown-protocol (a CommonMark subset) + html-markdown.
- [[file+emacs:pyparsing.org][pyparsing / Lark]] (#91, #321). Mature: esrap (PEG), cl-yacc (LALR), parcom, MaxPC, smug.
- [[file+emacs:dotenv.org][python-dotenv / pydantic-settings]] (#35, #74). Usable: TOML parsers (tomlet, pp-toml, clop), envy, ubiquitous; the .env loaders are dormant. cl-stack: cl-stack-config 0.3.0 (TOML / INI / .env + env, typed settings).

** Text and time
- [[file+emacs:dateutils.org][Dateutil]] (#15). local-time is the de facto standard: no recurrence, fuzzy parsing or durations. periods (ranges, recurrence) and calendar-times had commits in 2025; local-time-duration, chronicity and cl-date-time-parser are dormant.
- [[file+emacs:regex.org][re / regex]] (stdlib, #93). Mature: CL-PPCRE (the standard), one-more-re-nightmare (faster DFAs, no backreferences), str.
- [[file+emacs:jinja2.org][Jinja]] (#37). Mature: Djula (Django templates, closest to Jinja), Spinneret, CL-WHO (no auto-escaping), TEN, cl-mustache, Clip.

** Data
- [[file+emacs:sqlalchemy.org][SQLAlchemy / DB drivers]] (#86). Mature: CL-DBI + SxQL + Mito (the usual pick), Postmodern (PostgreSQL), cl-sqlite. CLSQL is old and heavy.
- [[file+emacs:pandas.org][pandas / pyarrow]] (#38, #78). Gaps: data frames in Lisp-Stat and vellum, cl-duckdb for big CSV and Parquet files, cl-csv.
- [[file+emacs:numpy.org][NumPy]] (#21). Partial: no vectorized arithmetic in the standard. MAGICL (BLAS / LAPACK, used in production), numericals (NumPy-like, SIMD), array-operations, LLA; Petalisp is research-grade, NumCL dormant.
- [[file+emacs:scipy.org][SciPy / statsmodels]] (#95, #570). Weak: Lisp-Stat (distributions, statistics, numerical-utilities) is active; GSLL is dormant since 2018 and needed a CFFI patch to install in 2025; linear-programming, Napa-FFT3.
- [[file+emacs:sympy.org][SymPy]] (#218). Mature: Maxima is a full CAS written in CL (5.50.0), with maxima-interface for calling it from Lisp.
- [[file+emacs:matplotlib.org][matplotlib / Plotly]] (#172, #413). Weak: Lisp-Stat plot (Vega-Lite in a browser), gnuplot wrappers (vgplot, eazy-gnuplot, clgplot), cl-matplotlib (Python bridge, new). cl-stack: canvas-protocol SVG charts.
- [[file+emacs:jupyter.org][Jupyter / IPython]] (#1016, #277). Usable: common-lisp-jupyter (kernel, widgets), maxima-jupyter, icl; SLIME / SLY / org-babel cover much of it.
- [[file+emacs:redis.org][redis-py]] (#140). Usable: cl-redis (full command set, RESP2, 2025-02); cl-redis-kit (new). cl-stack: cache-protocol + RESP3 backend, cache commands only.
- [[file+emacs:cachetools.org][cachetools / functools.lru_cache]] (#127). Usable: function-cache (LRU, TTL), fare-memoization; a memo macro is a few lines.

** AI and machine learning
- [[file+emacs:openai.org][OpenAI / Anthropic SDKs]] (#97, #164). Third-party clients are small (cl-completions, openai-openapi-client, Ollama clients). cl-stack is strong: llm-protocol with OpenAI-compatible and Anthropic wires, streaming, tools, embeddings, llama.cpp in-process.
- [[file+emacs:langchain.org][LangChain / LlamaIndex / MCP SDK]] (#198, #2737, #116). Third-party: MCP servers for a live image (cl-mcp, 40ants-mcp, mcp-lisp) and image-resident agents (Autolith, nodecode). cl-stack: ai-agent-protocol, mcp-protocol, rag-protocol, A2A, AG-UI.
- [[file+emacs:pytorch.org][PyTorch / TensorFlow / transformers]] (#397, #1040, #269). Weak: MGL (active, small), Caten (WIP), cl-waffe2 archived, cl-torch early; py4cl2 calls Python. cl-stack runs GGUF models through llama.cpp.
- [[file+emacs:sklearn.org][scikit-learn]] (#155). Weak: CLML (compatibility fixes), cl-random-forest, cl-online-learning, cl-libsvm; no shared fit / predict toolkit.

** Documents and media
- [[file+emacs:pillow.org][Pillow / OpenCV]] (#43, #449). Usable: opticl (quiet since 2022), imago, codecs zpng / cl-jpeg / skippy; OpenCV bindings are small. cl-stack: image-protocol 0.2.0 (decode / encode, resize, crop, rotate, composite).
- [[file+emacs:openpyxl.org][openpyxl / XlsxWriter / python-docx]] (#103, #206, #258). Usable: cl-excel (read and write .xlsx / .ods), cl-docx (new); nothing for .pptx. cl-stack reads DOCX and XLSX (doc-extract-protocol 0.4.0).
- [[file+emacs:pdf.org][pypdf / ReportLab / PyMuPDF]] (#187, #335, #262). Generation mature but quiet: cl-pdf, cl-typesetting. Reading: cl-stack doc-extract-backend-pdf (PDFium).

** Messaging and jobs
- [[file+emacs:kafka.org][Kafka / RabbitMQ / NATS clients]] (confluent-kafka #494, pika #1092). Weak: cl-rdkafka (2024-11), cl-rabbit (2021), cl-bunny (2020); cl-nats (2026-03). cl-stack mq-protocol backends do not reach a broker yet.
- [[file+emacs:celery.org][Celery / RQ / APScheduler]] (#452, #1120, #513). Weak: psychiq (Sidekiq-compatible, 2024-04), cl-cron, clerk; jobs usually run as threads in the image. cl-stack: task-protocol (durable steps, cron timers).
- [[file+emacs:email.org][smtplib / email / imaplib]] (stdlib). Usable: cl-smtp (TLS, AUTH), cl-mime, post-office / trivial-imap. cl-stack: mail-protocol (SMTP without AUTH / STARTTLS, IMAP over your stream).

** System
- [[file+emacs:pathlib.org][pathlib / os.path / shutil]] (stdlib). Mature: UIOP first, then cl-fad, pathname-utils, filepaths, osicat.
- [[file+emacs:subprocess.org][subprocess]] (stdlib). Mature: UIOP ~run-program~ / ~launch-program~, cmd, inferior-shell, async-process. No psutil.
- [[file+emacs:asyncio.org][asyncio]] (stdlib). No async/await; threads, futures and actors are mature: bordeaux-threads, lparallel, blackbird, sento, chanl. cl-async gets occasional fixes. cl-stack: event-protocol 0.3.0 has ~run-promise~ and ~gather~.
- [[file+emacs:logging.org][logging / structlog]] (stdlib, #273). Mature: log4cl (quiet upstream since 2023-03) with log4cl-extras for JSON and context fields, verbose, vom.
- [[file+emacs:click.org][Click / argparse]] (#20, stdlib). Mature: clingon (the usual pick), adopt, command-line-args, defmain, clon. unix-opts is dormant.
- [[file+emacs:multiprocessing.org][multiprocessing / concurrent.futures / joblib]] (stdlib, #169). Mature: no GIL, so threads cover it: bordeaux-threads, lparallel (pmap, futures), Sento, ChanL.
- [[file+emacs:psutil.org][psutil]] (#101). Usable: machine-state (processes, memory, disks, network, GPU; four OSes); osicat for POSIX.
- [[file+emacs:docker.org][Docker SDK]] (#228). Weak: docker-client (2022, no README); the docker CLI through a subprocess. cl-stack: compute-protocol sandboxes on podman or docker.
- [[file+emacs:gitpython.org][GitPython]] (#220). Usable: legit (git CLI), cl-git (libgit2, moved to sourcehut), cairn (pure CL, new). cl-stack: revision-backend-git (history, refs, diffs).
- [[file+emacs:rich.org][Rich / tqdm / prompt_toolkit / Textual]] (#57, #69, #153, #406). Usable: cl-tuition (Elm-style TUIs), cl-ansi-text, cl-ansi-term, cl-readline, croatoan. cl-stack: tui-protocol, tui-markdown.
- [[file+emacs:tkinter.org][tkinter / PyQt / PySide]] (stdlib, #3090, #2093). Many, none dominant: CLOG (browser, most active), nodgui (Tk), McCLIM 1.0, cl-gtk4; no Qt 5 / 6 binding. GUI tops the 2024 survey's wish list.

** Security, testing and tooling
- [[file+emacs:cryptography.org][cryptography / hashlib / PyJWT]] (#9, #36). Primitives mature, no recipes: Ironclad (v0.61, pure Lisp), cl+ssl. jose (JWT) is in cl-repo.
- [[file+emacs:pytest.org][pytest]] (#25). Mature: FiveAM (most used, slow releases), Parachute, Rove. Rove's parametrize, fixtures and JUnit XML are open PRs. Prove is deprecated; Fiasco and lisp-unit2 are dormant.
- [[file+emacs:hypothesis.org][Hypothesis]] (#384). Usable: FiveAM's ~for-all~ (no shrinking); check-it shrinks but is dormant since 2015.
- [[file+emacs:mypy.org][mypy]] (#160). The compiler is the checker: SBCL warns on declared and derived types; Coalton adds a static type system.
- [[file+emacs:packaging.org][pip / Poetry / uv]] (#215 uv, #500 Poetry). Quicklisp (63% in 2024), Ultralisp, Qlot (locks), ocicl, vend; Roswell and Deploy for executables. cl-stack: cl-repo.

* Weak or partial
:PROPERTIES:
:UNNUMBERED: t
:CUSTOM_ID: weak-or-partial
:END:
Libraries exist, but they are small, old, experimental or cover part of the job. Each has a page.

- Deep learning: MGL (active, small), Caten (work in progress); call PyTorch through py4cl2. See [[file+emacs:pytorch.org][PyTorch]].
- scikit-learn, SciPy: CLML, cl-random-forest; Lisp-Stat for statistics; GSLL is dormant. See [[file+emacs:sklearn.org][scikit-learn]], [[file+emacs:scipy.org][SciPy]].
- Plotting: Vega-Lite (Lisp-Stat plot) or gnuplot wrappers; no native library with matplotlib's range. See [[file+emacs:matplotlib.org][matplotlib]].
- Notebooks: common-lisp-jupyter. See [[file+emacs:jupyter.org][Jupyter]].
- Browser automation: cl-webdriver-client (2024-09), cl-cdp (new); cl-stack's browser-protocol launches Chrome since 0.2.0. See [[file+emacs:scrapy.org][Playwright]].
- Cloud SDKs: Pirá (AWS, alpha), aws-sdk-lisp (alpha); cl-azure (2016) and small Google clients. See [[file+emacs:boto3.org][boto3]], [[file+emacs:cloud.org][Google Cloud / Azure]].
- Kafka, RabbitMQ: cl-rdkafka, cl-rabbit, cl-bunny, all quiet. See [[file+emacs:kafka.org][Kafka]].
- Task queues: psychiq, cl-cron, clerk. See [[file+emacs:celery.org][Celery]].
- SSH: cl-ssh, conch (both 2026, young). See [[file+emacs:paramiko.org][Paramiko]].
- Docker: docker-client (2022). See [[file+emacs:docker.org][Docker]].
- System monitoring: machine-state covers psutil's ground in one library; osicat for POSIX. See [[file+emacs:psutil.org][psutil]].

* What the survey and reviews say
:PROPERTIES:
:UNNUMBERED: t
:END:
[[https://blog.djhaskin.com/blog/common-lisp-community-survey-2024-results/][Common Lisp Community Survey 2024]] (Dan Haskin, 2024-08-09, 293 respondents). No 2025 or 2026 results had been published by November 2026.
- SBCL is the daily driver of 88%.
- Dependencies: Quicklisp 63%, Ultralisp 17%, Qlot 9%, OCICL 3%.
- In use:

| Area       | Top answers                                                     | Pages                             |
|------------+-----------------------------------------------------------------+-----------------------------------|
| JSON       | cl-json 23%, jzon 19%, yason 7%, shasht 4%                      | [[file+emacs:json.org][json]]     |
| Web server | Hunchentoot 36%, Clack / Woo 7%                                 | [[file+emacs:flask.org][Flask]]   |
| Framework  | Caveman2 7%, home-grown 4%, Ningle 3%, CLOG 3%; two thirds none | [[file+emacs:flask.org][Flask]]   |
| Testing    | FiveAM 28%, Parachute 11%, Rove / Prove 7%                      | [[file+emacs:pytest.org][pytest]] |

| XML        | Plump 14%, CXML 6%, xmls 4%; 70% need none                      | [[file+emacs:lxml.org][lxml]]     |

- Wanted (the author's summary of free-form answers): GUI ([[file+emacs:tkinter.org][tkinter]]), ML ([[file+emacs:pytorch.org][PyTorch]], [[file+emacs:sklearn.org][scikit-learn]]), gRPC ([[file+emacs:protobuf.org][protobuf / gRPC]]), cryptography, OpenAPI, better web frameworks, an AWS SDK ([[file+emacs:boto3.org][boto3]]). Graphics, databases, math / statistics and concurrency lead the categories respondents want surveyed next.

Ecosystem reviews:
- vindarel, [[https://lisp-journey.gitlab.io/blog/these-years-in-common-lisp-2023-2024-in-review/][These years in Common Lisp: 2023-2024 in review]] (2025-02-17): jzon 1.0, Bordeaux-Threads API v2, Sento 3, CLOG 2.0, calendar-times; numericals, Petalisp, cl-waffe2 and Lisp-Stat for numerics. Quicklisp updated 2024-10-12 after a year's pause; ocicl, Qlot 1.5 and vend as alternatives.
- vindarel, [[https://lisp-journey.gitlab.io/blog/csv-parsing-in-common-lisp/][CSV parsing in Common Lisp, data frames]] (2026-11-07): cl-csv for simple use, DuckDB for speed, Lisp-Stat for data frames.
- [[https://aliquote.org/post/cl-tooling-in-2025/][Common Lisp tooling in 2025]] (2025-01-22): GSLL and common-lisp-jupyter needed a CFFI patch to install; MAGICL installed cleanly; cl-ana failed on its HDF5 bindings.

Recommended vs abandoned, from the pages' last commits:
- The usual picks are maintained: jzon (2026-03), Hunchentoot (2026-05), Plump (2026-04), CL-PPCRE (2025-06), Mito (2026-04), local-time (2026-05), clingon (2026-11), Ironclad (2026-11), Parachute (2026-07). FiveAM, the most used test framework, last changed 2024-09.
- The most used JSON library is not: cl-json (2022-05). Neither are jonathan (2020-09), NumCL (2022-10), unix-opts (2021-01), chronicity (2019-01), local-time-duration (2018-04).
- Archived or deprecated: cl-yaml, cl-html5-parser, Prove.
- Moved to Codeberg: Shinmera's libraries (Plump, Parachute, Radiance, verbose, Clip, ratify, pathname-utils); Plump and Parachute in 2025-08.

* Since 2020
:PROPERTIES:
:UNNUMBERED: t
:END:
The [[https://github.com/egao1980/python-to-cl/tree/1846916][2020 version]] of this site had two pages: Requests (Drakma, Dexador) and Dateutil (local-time, local-time-duration, chronicity, an Easter gist). Examples loaded with ~ql:quickload~ and the site ran on Read the Docs.

Now:
- 56 pages in nine areas, each with last-commit dates, versions and a verdict per library, plus the cl-stack libraries, and a [[file+emacs:usecases.org][use-case index]].
- Dexador (2026-10) and Drakma (2026-09) are both maintained; local-time is still the de facto standard. local-time-duration (2018-04) and chronicity (2019-01) have not changed since.
- Examples load from [[https://github.com/egao1980/cl-repository][cl-repo]] (~ghcr.io/egao1980/cl-systems~) instead of Quicklisp, and run on SBCL 2.4.11. Libraries cl-repo does not carry are marked "not run".
- New pitfall: Homebrew's OpenSSL 4 breaks cl+ssl on macOS (see [[file+emacs:requests.org][Requests]]).
- The site is built from the .org pages by [[https://github.com/egao1980/cl-blog][cl-blog]] and served by GitHub Pages.

* Loading libraries
:PROPERTIES:
:UNNUMBERED: t
:END:
Examples load libraries with [[https://github.com/egao1980/cl-repository][cl-repo]] from ~ghcr.io/egao1980/cl-systems~, not Quicklisp:

#+begin_src sh
curl -fsSL https://raw.githubusercontent.com/egao1980/cl-repository/main/install.sh | bash
mkdir demo && cd demo
echo '(defsystem "demo" :depends-on ("dexador" "cl-stack-http"))' > demo.asd
cl-repo sync
cl-repo ros run
#+end_src

Then ~(asdf:load-system "dexador")~ in the REPL. Since cl-repo 0.27.35 ~cl-repo ros~ starts without Roswell's Quicklisp (~-Q~ brings it back), so a system missing from the project fails instead of loading from Quicklisp.

Libraries that are not in cl-repo are shown with their documented examples, marked "not run". Results come from SBCL 2.4.11 on macOS arm64, 2026-11-23; the examples the [[file+emacs:updates.org][updates]] touch were re-run on 2026-11-24 with the versions listed there. Some examples use local services: Valkey 8, Mailpit and alpine containers in Docker, Google Chrome (browser automation), a local mock of the OpenAI and Anthropic APIs ([[https://github.com/egao1980/python-to-cl/blob/master/examples/mock-llm.lisp][examples/mock-llm.lisp]]), and a 260K-parameter GGUF model from Hugging Face.
