* multiprocessing / concurrent.futures / joblib
:PROPERTIES:
:UNNUMBERED: t
:END:
https://docs.python.org/3/library/multiprocessing.html

https://docs.python.org/3/library/concurrent.futures.html

multiprocessing is a package that supports spawning processes using an API similar to the threading module.

** Features
:PROPERTIES:
:UNNUMBERED: t
:END:
+ multiprocessing: ~Process~, ~Pool.map~, queues, shared memory; works around the GIL
+ concurrent.futures: thread and process pool executors, futures, ~as_completed~
+ joblib: ~Parallel(delayed(f)(x) for x in xs)~, result caching

** Common Lisp alternatives
:PROPERTIES:
:UNNUMBERED: t
:END:
No GIL: SBCL, CCL, LispWorks and ECL threads run Lisp code on all cores, so the thread libraries cover what Python needs processes for.

Gap: cl-stack-executors has no futures or ~pmap~; results come back through your own lock or channel. On the loop side event-protocol 0.3.0 gathers ~submit-promise~ results ([[https://github.com/egao1980/event-protocol/issues/26][event-protocol#26]], fixed).

*** Threads
#+begin_src lisp :exports source :results silent
(asdf:load-system "bordeaux-threads")
(asdf:load-system "cl-stack-executors")
(asdf:load-system "process-backend-uiop")

(defun collatz-steps (n)
  (loop for x = n then (if (evenp x) (/ x 2) (1+ (* 3 x)))
        until (= x 1) count t))
#+end_src

~pool.map~ on plain threads, one per item:
#+begin_src lisp
(mapcar #'bt2:join-thread
        (loop for n from 1 to 8
              collect (let ((n n)) (bt2:make-thread (lambda () (collatz-steps n))))))
#+end_src

#+RESULTS:
: (0 1 7 2 5 8 16 3)

*** cl-stack
A bounded pool, ~ThreadPoolExecutor(4)~:
#+begin_src lisp
(let ((pool (stack-executors:make-thread-pool :workers 4))
      (results (make-array 8))
      (lock (bt2:make-lock))
      (done (bt2:make-condition-variable))
      (left 8))
  (dotimes (i 8)
    (let ((i i))
      (stack-executors:executor-submit
       pool (lambda ()
              (setf (aref results i) (collatz-steps (1+ i)))
              (bt2:with-lock-held (lock)
                (when (zerop (decf left)) (bt2:condition-notify done)))))))
  (bt2:with-lock-held (lock)
    (loop until (zerop left) do (bt2:condition-wait done lock)))
  (stack-executors:executor-shutdown pool)
  results)
#+end_src

#+RESULTS:
: #(0 1 7 2 5 8 16 3)

~pool.map~ on the event loop's pool, ~gather~ keeps the order:
#+begin_src lisp
(asdf:load-system "event-backend-libuv")
(asdf:load-system "event-protocol/promises")
(event-protocol/promises:run-promise
 (lambda ()
   (apply #'event-protocol/promises:gather
          (loop for n from 1 to 8
                collect (let ((n n))
                          (event-protocol/promises:submit-promise
                           event-protocol:*event-loop* (lambda () (collatz-steps n)))))))
 :backend (event-backend-libuv:make-libuv-backend))
#+end_src

#+RESULTS:
: (0 1 7 2 5 8 16 3)

Processes, ~multiprocessing.Process~: three one-second workers in parallel:
#+begin_src lisp
(let* ((start (get-internal-real-time))
       (workers (loop for i from 1 to 3
                      collect (stack-process:launch (list "sh" "-c" (format nil "sleep 1; exit ~d" i))))))
  (list (mapcar #'stack-process:wait workers)
        (round (- (get-internal-real-time) start) internal-time-units-per-second)))
#+end_src

#+RESULTS:
: ((1 2 3) 1)
