* pip / Poetry / uv
:PROPERTIES:
:UNNUMBERED: t
:END:
https://docs.astral.sh/uv/

https://python-poetry.org/docs/

An extremely fast Python package and project manager, written in Rust.

** Features
:PROPERTIES:
:UNNUMBERED: t
:END:
+ pip: install from PyPI; venv: isolated environments
+ Poetry / uv: ~pyproject.toml~ projects, dependency resolution, lock files, workspaces
+ uv: Python version management, tool runs (~uvx~), very fast installs
+ Build and publish wheels; PyInstaller: single-file executables

** Common Lisp alternatives
:PROPERTIES:
:UNNUMBERED: t
:END:
[[https://asdf.common-lisp.dev/][ASDF]] (the ~.asd~ system definition, ~pyproject.toml~'s role) ships with every implementation. The managers below fetch what ASDF loads. The 2024 survey: Quicklisp 63%, Ultralisp 17%, Qlot 9%, OCICL 3%, CLPM 2%.

Executables: ~sb-ext:save-lisp-and-die~ writes the whole image as one binary (example below). Distribution packages: Guix and Nix carry many Common Lisp libraries (2% and 1% in the 2024 survey, both write-ins); the [[https://lisp-journey.gitlab.io/blog/state-of-the-common-lisp-ecosystem-2020/][2020 review]] saw Guix as a contender to Roswell for reproducible setups.

*** cl-stack
| Library                                                                  | Version | Verdict                                                                                                                                                                                                                           |
|--------------------------------------------------------------------------+---------+-----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------|
| [[https://github.com/egao1980/cl-repository][cl-repository]] (~cl-repo~) | 0.27.39 | OCI packages on GHCR (~ghcr.io/egao1980/cl-systems~) with native libraries per platform; dependencies from the ~.asd~, a ~cl-repo.lock~; ~sync~ / ~test~ / ~run~ / ~ros~ / ~publish~. Every example on this site runs through it. |

Fixed on 2026-11-23 in 0.27.35 ([[https://github.com/egao1980/cl-repository/pull/174][cl-repository#174]]): ~cl-repo ros~ starts without Roswell's Quicklisp (~-Q~ brings it back, [[https://github.com/egao1980/cl-repository/issues/166][#166]]); the lock records each package's registry and digest, so a fresh machine syncs from it ([[https://github.com/egao1980/cl-repository/issues/163][#163]]); ~sync~ resolves to the newest published version ([[https://github.com/egao1980/cl-repository/issues/167][#167]]) and names the versions the registry has when a minimum is missing ([[https://github.com/egao1980/cl-repository/issues/165][#165]]); a qlfile-only project gets its entries' dependencies ([[https://github.com/egao1980/cl-repository/issues/170][#170]]); parallel runs on SBCL no longer race on the shared fasl cache ([[https://github.com/egao1980/cl-repository/issues/162][#162]]; other Lisps and Windows: [[https://github.com/egao1980/cl-repository/issues/173][#173]]); the misleading "stays loaded" warning is gone ([[https://github.com/egao1980/cl-repository/issues/169][#169]]; the image did load the lock's versions). 0.27.36 stops implementation systems such as ~uiop~ from becoming solver requests ([[https://github.com/egao1980/cl-repository/issues/171][#171]]). 0.27.37 – 0.27.39 (2026-11-24): private packages with credentials from the environment ([[https://github.com/egao1980/cl-repository/issues/186][#186]]); with no registry reachable, ~sync~ fails fast instead of taking minutes ([[https://github.com/egao1980/cl-repository/issues/179][#179]]); ~cl-repo --version~ ([[https://github.com/egao1980/cl-repository/issues/189][#189]]); build output stays off stdout ([[https://github.com/egao1980/cl-repository/issues/194][#194]]). Gaps: the client tree and the install tree share a fasl root ([[https://github.com/egao1980/cl-repository/issues/182][#182]]).

** Which implementation
:PROPERTIES:
:UNNUMBERED: t
:END:
Python has one implementation most people run, CPython. Common Lisp has a standard (ANSI, 1994) and several implementations; portable libraries run on most of them, so the choice is about speed, platform and embedding. SBCL is the default: 88% of the 2024 survey use it daily, and g000001's [[https://zenn.dev/g000001/articles/e4eb6ab1c9040f03eafa][2026 implementation roundup]] (in Japanese, revised 2026-08-01) recommends it first. Versions are the latest releases on 2026-11-26.

| Implementation | Latest                  | Pick it for                                                                                                | Limits                                                                                                                        |
|----------------+-------------------------+------------------------------------------------------------------------------------------------------------+-------------------------------------------------------------------------------------------------------------------------------|
| SBCL           | 2.6.10 (2026-10-29)     | The default. Native code, among the fastest in the Lisp family; a release a month; what libraries test on. | Compiles more slowly than CCL; images are large (36 MB for the hello world below).                                            |
| CCL            | 1.14 (2026-10-28)       | Very fast compiles. Native on Apple silicon and ARM64 Linux since 1.14.                                    | Before 1.14, ARM Macs ran the Intel build under Rosetta 2 (the roundup, revised before 1.14, still says so). Revived in 2024. |
| ECL            | 26.5.5 (2026-05)        | Embedding in C programs: compiles Lisp to C and links as a library. A WebAssembly port is in development.  | Slower code than SBCL.                                                                                                        |
| ABCL           | 1.9.3                   | The JVM: calls Java directly; ANSI conformance and MOP support have improved.                              | JVM start-up; Unicode lagged the others in 2015.                                                                              |
| Clasp          | 2.7.0 (2025-01)         | C++ interop through LLVM.                                                                                  | Not mature for general use, per the roundup; take prebuilt or nightly binaries, not a source build.                           |
| LispWorks      | 8.1.2                   | Cross-platform desktop GUIs with CAPI (Windows, macOS, GTK on Linux); fast compiles and code.              | Commercial: Hobbyist licence $750 (64-bit). The free Personal Edition stops after 5 hours and has a heap limit.               |
| Allegro CL     | 11.0                    | Commercial support and a large built-in library.                                                           | Prices on request. The free Express Edition has a heap limit; 11.0 gave it 64-bit and SSL.                                    |
| CLISP          | no release in ten years | Learning: a friendly REPL.                                                                                 | Quicklisp libraries increasingly fail to install or run.                                                                      |
| GCL            | 2.7.1 (2025-04)         | Maxima and ACL2. ANSI-conformant since 2.7.1 (~GCL_ANSI=1 gcl~, not run).                                  | No UTF-8; ASDF and Quicklisp mostly fail.                                                                                     |

The roundup no longer recommends CMUCL (still 32-bit only). Secondary use in the 2024 survey: ECL 13%, CCL 13%, ABCL 5%, LispWorks 5%, Allegro 3%, Clasp 2%. Borretti's 2015 review gave the same split: SBCL or CCL for new users, ECL for embedding, ABCL for the JVM. The [[https://common-lisp.net/implementations/][common-lisp.net list]] adds experimental implementations new in 2026: dotcl (.NET) and Clysm (WebAssembly GC).

The examples on this site run on SBCL. ~cl-repo ros -L ccl-bin~ and ~-L abcl-bin~ fail before the first form on cl-repo 0.27.39: the startup form uses SBCL-only ~#A~ string syntax ([[https://github.com/egao1980/cl-repository/issues/203][cl-repository#203]]).

*** Executables
PyInstaller's ~--onefile~ role: ~save-lisp-and-die~ writes the image with a ~:toplevel~ function.
#+begin_src python
# pyinstaller --onefile hello.py
import sys, platform
print("hello from", platform.python_implementation(), platform.python_version(), "args", sys.argv[1:])
#+end_src

~hello.lisp~:
#+begin_src lisp :exports source
(defun main ()
  (format t "hello from ~a ~a, args ~s~%"
          (lisp-implementation-type) (lisp-implementation-version)
          (uiop:command-line-arguments))
  (uiop:quit 0))
#+end_src

#+begin_src sh
cl-repo ros +Q run -- --load hello.lisp \
  --eval '(sb-ext:save-lisp-and-die "hello" :toplevel (function main) :executable t)'
./hello a b
#+end_src

#+RESULTS:
: hello from SBCL 2.4.11.roswell, args ("a" "b")

The binary is 36 MB: the whole image, compiler included. ~:compression t~ shrinks it on an SBCL built with zlib or zstd; Deploy adds the foreign libraries; tree-shaker (above) drops unused code. ~ros build hello.ros~ does the same for a Roswell script.
